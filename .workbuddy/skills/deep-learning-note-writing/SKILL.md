# 深度学习笔记撰写

## 用途

把用户反复确认过的写作规范固化为一套可执行流程，保证同一系列的多篇笔记在结构、符号、图表、语言风格上完全一致，并让初学者读得懂、学得下去。

## 何时使用

- 在 `~/Documents/github/Deep Learning Notes` 下新建 / 重写 / 扩写笔记
- 为笔记绘制或重绘 SVG 配图
- 规划多篇笔记的系列结构（模块划分、前后依赖）
- 校对已有笔记是否违反规范

## 工作流

1. **读上下文**：读同主题已有笔记，确认符号、术语、图风格；读 `references/note-template.md` 取骨架。
2. **定结构**：先列本篇的“问题 → 原始设计 → 前沿演化 → 小结表”，确认模块边界，不与其他篇重复。
3. **画图**：按 `references/figure-spec.md` 绘制，图内公式转 path，渲染后逐张检查重叠与溢出。
4. **写正文**：按下方“硬性规范”逐条执行。
5. **自检**：过一遍文末检查清单，特别是符号一致性、公式是否全部 LaTeX、图注是否论文风格。

## 硬性规范

### 一、篇章结构（每篇固定，顺序不变）

1. 开头 ≤ 5 行：一句话结论（本质是什么，加粗）+ 3 条要点，供速览与复习。紧随其后放**篇首总览图**：一幅图给出全篇地图，按主题选型——流程类画数据流（本模块在整机中的位置 + 内部结构），演化类画谱系（原始设计到前沿的主线），对比类画对照示意。总览图必须承载本篇主线信息，不做装饰图；图内公式转 path，图注一句话点明“看这张图要抓住什么”。
2. 开头写前置依赖，链到对应文件（相对路径）。
3. 正文四段式：它解决什么问题（没有它会怎样）→ 原始设计（含公式与直觉）→ 前沿演化 → 小结表。
4. 倒数第二节：**面试向易错点表**，四栏固定为「面试考点 / 常见答错 / 正确答法 / 面试官在考什么」。考点写成面试官会问的原话；答错写真实会出现的错答；正确答法一两句可直接说出口；最后一栏点出考查意图。按“大厂 NLP 岗常问”筛选，不堆偏题。
5. 末节：引用论文。编号列表，格式 `作者. 标题. 会议/arXiv, 年份. arXiv 编号 + 链接`；正文中用（Vaswani et al., 2017）式括号标注，不打断阅读。
6. 每节开头一句“本节要回答的问题”。
7. 篇幅 3000–5000 字、3–5 张图（注意力篇可放宽到 6000）。
8. 不放代码。定位是理解原理，代码另开系列。
9. 难度分层：主线必须一路可通读；延伸细节放进“进阶框”，标注“跳过不影响后续”。

### 二、内容

10. 每个前沿设计必须挂在它解决的旧局限上（RoPE 挂在“正弦编码靠加法、注意力层感受不到位置”上，GQA 挂在“KV cache 太大”上），不做名词罗列。
11. 前沿截止线：讲到当今主流模型在用的方案为止（RoPE / SwiGLU / RMSNorm / GQA / FlashAttention 这一类），更远的只进演化谱系图提名字，不展开。
12. 固定例句（全系列共用）：`科软 放 实习 吸引 学生 报考` —— 6 个词、11 个 token（科/软/放/实/习/吸/引/学/生/报/考）。每篇都拿它算，读者看到的是“老朋友的下一段旅程”。
13. 公式三件套：公式 + 符号逐个解释 + 带具体数字的代算例。
14. 先给错误直觉再纠正（“注意力不是复制粘贴，是加权平均”），纠偏比灌输有效。
15. 晦涩知识必须配图 + 直观例子。

### 三、符号与术语

16. 初次引用某符号时，**严格使用论文原符号**。
17. 两篇论文符号冲突时，沿用**第一次出现的符号**，另一篇的不同写法在紧邻括号里标注，如 $L$（原文记 $L_{seq}$）。不建全局符号表，太冗余。
18. 不引入未定义符号，符号全局唯一。系列约定：$L$ = 序列长度、$N$ = 层数、$n$ = 源句长度、$m$ = 目标句长度、$d$ = 模型维度。
19. 术语全文唯一，不换词（定了“注意力头”就不再写 head）。术语首次出现**一律英文在前、中文在后**：`Tokenizer（分词器）`、`Feed-Forward Network, FFN（前馈网络）`；**绝不写成“分词器（tokenizer）”**。中文只作为英文术语的注解出现，后续行文可用中文简称，但术语锚点始终是英文。

### 四、表达

20. 每句都要有因果，零废话。禁两类句子：无推理支撑的跳步结论、同义反复的废话（“读数明显不同”当结论）。结论必须能从图中或公式中直接推出。
21. 类比必须标注边界（“多转速 ≈ 多进制计数（类比，不是等价）”）。
22. 严谨推导不跳步，引理先给，再接直观例子；结论要落到精髓（“唯一”≠“能编码位置”，要讲同态、等比、与点积相容）。
23. 单段 ≤ 5 行；连续公式之间必须有文字过渡，禁止公式墙。
24. 中文推理逻辑组织：先问题 → 动机 → 推导 → 结论，不照搬英文论文的平铺顺序。

### 五、图与公式

25. 模块图严格照参考论文的形式与布局，不自己发明画法；无对应论文图时，按数据流自上而下或自左而右。
26. 图内语言分两类，不要一刀切：
    - **术语用英文，且不翻译**：Tokenizer、Token、Embedding、Attention、Softmax、BPE、logits、KV cache 等论文与工程里的通用叫法，保持原词。
    - **解释性文字用中文**：图里那些描述性句子（“按语料学到的合并规则”“词表达到目标大小即停止”“从未被合并，各自一个 token”）一律写中文，照顾英语不好的读者。
    - 全图**不做逐处中英对照**（不写“分词器 (Tokenizer)”），术语的中文解释只在正文首次出现时给一次；图内不做整句英文。
27. 图注按论文风格简洁：图号 + 一句说明图展示什么，必要时加一句关键提示，不冗长；详细解读放正文。
28. 矩阵图方向固定：行 = 位置 $i$（token 序号），列 = 维度 $j$。与 d2l 等资料的画图习惯冲突时，以本约定为准并主动指出差异。
29. 正文公式一律 LaTeX（`$...$` / `$$...$$`）。
30. 图内公式必须走仓库 `.tools/latex2svg` 工具链（`tex2frag.js` + `figbuild.mjs` + resvg 3x 白底）转成 path，不许用普通 text 冒充公式。

### 六、系列组织

31. 模块篇按数据流排列：分词词表 → Embedding → 位置编码 → 注意力 → FFN → 残差+归一化 → 输出头/训练推理；装配篇放最后。
32. 装配篇只讲跨模块关系（数据流、mask 体系、交叉注意力、训练 vs 推理、三种拓扑），对已讲模块只给一句话结论 + 指回链接，不重复推导。
33. KV cache 归注意力篇（本质是 K/V 不重算）；交叉注意力与 mask 体系归装配篇（单看零件看不出差异）。
34. 每个模块一个文件夹，md 与 `figs/` 同级，图片命名 `fig_<模块>_<主题>.svg`。

### 七、协作

35. 全局替换、术语更换这类决定，先给选项、确认后再动文件。
36. 用户会在编辑器里手改 md：每次改动前 diff 备份，保留其手改内容（含插入的括号注释），不整篇覆盖。

## 自检清单（交付前逐条过）

- [ ] 开头 5 行内有一句话结论 + 3 条要点
- [ ] 篇首有总览图，且承载本篇主线（非装饰图）
- [ ] 正文四段式齐全，末两节是易错点表 + 引用
- [ ] 所有公式都是 LaTeX，图内公式已 path 化
- [ ] 图内术语用英文、解释性文字用中文，未做逐处中英对照
- [ ] 符号首次出现与论文一致，冲突处括号标注，全篇无未定义符号
- [ ] 术语前后一致，首次出现为英文在前（`Tokenizer（分词器）`）
- [ ] 无跳步结论、无同义反复，类比都标了边界
- [ ] 每张图都渲染检查过：无重叠、无溢出、无文字截断
- [ ] 图片引用与 `figs/` 实际文件一一对应
- [ ] 引用列表完整，正文标注与列表对得上
